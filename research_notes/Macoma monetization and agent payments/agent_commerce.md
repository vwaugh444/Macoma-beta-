# How consumer AI agents place orders and pay (October 2026), and what Macoma should use

Method note: every page fetch (eesel.ai, instinct.com, stripe.com, parallel.ai and others) was refused by this session's egress proxy. The findings below come from web-search result summaries of the cited pages, plus Anthropic's API reference bundled with the claude-api skill (cached 2026-10-06), which points to platform.claude.com URLs. ## 1. How does Instinct place orders, buy groceries, book tickets and cancel subscriptions?

### Takeaway
Instinct does not use a special retailer network. It runs an LLM agent on its own cloud computer, with a browser, stored logins and 2FA handling, and it acts inside the user's accounts. To pay, it asks Stripe Link for a single-use card for the approved amount. Since 28 Sep 2026 it also uses one partner API, Shopify's agent checkout with Shop Pay. Its terms make the user the buyer and Instinct the user's agent, and they cap Instinct's liability at roughly $100.

### Inferences
- Instinct's ordering stack has three layers: (a) a general cloud browser agent working in logged-in accounts; (b) Stripe Link one-time cards, which keep card numbers out of the agent's hands and add an approval step outside the chat; (c) partner rails such as Shopify and Shop Pay, which avoid scraping where they exist. Macoma can copy all three.
- The terms carry the legal model: the user is the buyer, the platform is the user's agent and not a party to the sale, disputes go to the merchant, and liability is capped. Macoma's terms will need the same structure, reviewed by counsel.
- Instinct's cloud browser holds the user's passwords and 2FA. That is its largest liability and trust problem. A service-business tool can avoid it by using supplier accounts, cart links or payment-only credentials.

- No Instinct job posts, technical docs or founder interviews describing the browser stack (vendor or in-house, CAPTCHA handling) were found.

- No primary detail was found on ticket booking specifically, for example whether it uses partner APIs or the browser.

## 2. Agent payment rails as of October 2026: status, who can use them, cost (including Apple Pay)

### Takeaway
A small US startup can realistically use only the Stripe layer today. That means Link's agent wallet (one-time cards or Shared Payment Tokens, with per-purchase approval in the Link app) and Stripe Issuing's virtual cards with spend controls (the agent-specific product is in private preview). Visa and Mastercard agentic tokens reach startups mainly through Stripe or Adyen rather than directly. ACP, AP2 and x402 are protocols that the merchant must also support. No source shows any way for an agent to use Apple Pay without a person present.

### Cited Findings
**Visa Intelligent Commerce (VIC), agentic tokens and Trusted Agent Protocol (TAP)**
- VIC launched in April 2025. It replaces card details with a tokenized credential confirming that the consumer authorized a specific agent within set limits. 2026 additions include an MCP server to VIC APIs and an Acceptance Agent Toolkit. — [nevermined.ai](https://nevermined.ai/blog/ai-agent-payments-visa-mastercard-rails); [stellagent.ai](https://stellagent.ai/insights/visa-mastercard-card-network-agentic-strategy)
- Visa Intelligent Commerce Connect was announced on 8 Apr 2026 as "a single integration that lets agents pay and merchants accept agentic transactions." It is in pilot with AWS, Highnote and Mesh. — [universalcommerceprotocol.fr](https://universalcommerceprotocol.fr/en/visa-mastercard-agentic-commerce/); [paz.ai](https://www.paz.ai/blog/card-networks-agentic-commerce)
- Visa and OpenAI announced agent payments in June 2026, with no launch date, merchant list or checkout design given. — [Digital Commerce 360, 12 Jun 2026](https://www.digitalcommerce360.com/2026/06/12/visa-openai-agent-led-payments/)
- TAP was announced on 14 Oct 2025 with Cloudflare. Agents sign requests (RFC 9421 HTTP Message Signatures, Web Bot Auth). Merchants check them against a Visa-run directory of agent keys. A tag marks whether the agent is browsing or paying, and a nonce prevents replay. TAP does not move money. Partners include Adyen, Checkout.com, Shopify, Stripe, Microsoft and Worldpay. — [Cloudflare blog](https://blog.cloudflare.com/secure-agentic-commerce/); [Finextra](https://www.finextra.com/blogposting/29617/deep-dive-the-role-of-visas-trusted-agent-protocol-in-agentic-commerce); [Business Wire](https://www.businesswire.com/news/home/20251014144421/en)

**Mastercard Agent Pay**
- Agent Pay launched in April 2025 on Agentic Tokens, which extend the tokenization used for contactless and card-on-file payments. Verifiable Intent followed on 5 Mar 2026. It is an open-source, tamper-resistant record that links shopper identity, instructions and outcome, for use in disputes. — [eco.com comparison](https://eco.com/support/en/articles/15192003-mastercard-agent-pay-vs-visa-trusted-agent-2026-compared); [nevermined.ai](https://nevermined.ai/blog/best-platforms-agentic-payments)
- Agent Pay for Machines (AP4M) launched in June 2026 for high-frequency, low-value machine payments. It has an early-access developer portal at ap4m.build/info. A 21 Oct 2026 report says Mastercard opened developer APIs for agent payments "built on x402." Dates differ between sources. — [finance-loop.net](https://www.finance-loop.net/mastercard-agent-pay/); [TechTimes, 21 Oct 2026](https://www.techtimes.com/articles/329316/20261021/mastercard-opens-developer-apis-ai-agent-payments-built-x402-protocol.htm)
- In practice, access comes through processors. Stripe added Agent Pay and VIC token support to Shared Payment Tokens in March 2026. Adyen Agentic launched on 16 Jun 2026 in limited availability for US enterprise merchants (single secondary source). Both networks also partnered with FIS so issuers can use "Know Your Agent." — [Stripe blog](https://stripe.com/blog/supporting-additional-payment-methods-for-agentic-commerce); [stellagent.ai](https://stellagent.ai/insights/mastercard-agent-pay-agentic-tokens); [eco.com](https://eco.com/support/en/articles/15192001-what-is-mastercard-agent-pay-ai-agent-commerce-protocol-in-2026)
- Some sources describe the standards (Visa TAP, Agent Pay, Google UCP, AP2) as still being written in 2026 rather than final. — [nevermined.ai](https://nevermined.ai/blog/best-platforms-agentic-payments)

**Stripe: Agentic Commerce Protocol (ACP) and Shared Payment Tokens (SPT)**
- OpenAI and Stripe co-developed ACP and released it under Apache 2.0 in September 2025. One guide says ChatGPT "Instant Checkout" was retired in March 2026 while the protocol continued; the latest stable spec is dated 2026-04-17 (single secondary source). — [eco.com ACP explainer](https://eco.com/support/en/articles/14845478-acp-agentic-commerce-protocol-explained)
- An SPT is a single-use credential tied to one merchant and one amount, with a time limit. It is Stripe's implementation of ACP delegated payment. In March 2026 SPTs were extended to Visa and Mastercard agentic tokens and to Affirm and Klarna. — [stellagent.ai SPT](https://stellagent.ai/insights/stripe-shared-payment-token-spt); [American Banker](https://www.americanbanker.com/payments/news/stripe-advances-security-for-agentic-commerce)
- Stripe's 22 Apr 2026 changelog adds a SharedPaymentGrantedToken object (public preview) with `agent_details` and `usage_limits`. It is passed on a PaymentIntent through `payment_method_data.shared_payment_granted_token`. — [Stripe changelog](https://docs.stripe.com/changelog/dahlia/2026-04-22/shared-payment-granted-token)
- The Agentic Commerce Suite is Stripe's packaging of these tools. — [Stripe newsroom](https://stripe.com/newsroom/news/agentic-commerce-suite); [mindstudio.ai](https://www.mindstudio.ai/blog/stripe-agentic-commerce-suite-5-new-primitives-ai-agents-buy-pay)

**Stripe Link wallet for agents (what Instinct, Meta Muse and Anthropic's Claude Duet use)**
- It launched on 29 Apr 2026. The user grants OAuth access, each spend is approved in the Link app, and the agent receives a one-time card or an SPT. Stripe said spending limits and approval-free purchases would come later. [corrected in verification] Hard caps already apply: the official `stripe/link-cli` repo lists $500 per spend request, $500 per day and $20,000 per 30 days per Link account, across all connected agents, and Link's support FAQ says the daily limit cannot be raised. The agent wallet is for US individual Link accounts only, and a request must be approved within 10 minutes with biometrics. Sources disagree on how long an approved card stays valid (12 h or 48 h). Some blogs quote $5,000 caps, but those conflict with the repo. — [TechCrunch](https://techcrunch.com/2026/04/30/stripe-link-digital-wallet-ai-agents-shopping/); [Stripe blog](https://stripe.com/blog/giving-agents-the-ability-to-pay)
- Browserless offers "Agentic Checkout with Stripe Link" through two MCP tools that type the one-time card into the merchant's checkout form. It is limited to US wallets paying in USD, up to $50 per purchase. [corrected in verification] Neither the Browserless page nor any other source stating the $50 cap could be found, so treat it as unverified. Link's own per-request cap is $500 (see above). — [Browserless blog](https://www.browserless.io/blog/agentic-checkout-stripe-link)
- On 21 Oct 2026 Anthropic announced Claude Duet, a proactive agent for professionals and small business owners that can "purchase things for your business using Link." It waits for approval before payments and is on a waitlist for US Pro and Max subscribers. — [PYMNTS, Oct 2026](https://www.pymnts.com/news/artificial-intelligence/2026/anthropics-new-ai-agent-purchases-business-supplies/)

**Stripe Issuing / Lithic virtual cards with spend controls**
- Stripe "Issuing for agents" is in private preview. It issues cards and credentials agents can use for autonomous purchases. Controls include per-agent limits, merchant-category limits (for example, airlines and hotels only), per-transaction or per-period limits, and single-use cards. — [Stripe docs: Issuing for agents](https://docs.stripe.com/issuing/agents)
- [corrected in verification] Stripe's own Issuing pricing page lists 10¢ per virtual card and $3.50 per standard physical card in the US, plus $15 per dispute and 1% + 30¢ on cross-border transactions. A third-party source gives the same card prices. Using a card from Issuing for agents in a PaymentMethod requires private-preview access, which you request through Stripe sales ([Stripe docs: programmatic checkout](https://docs.stripe.com/issuing/agents/programmatic-checkout); [Stripe Issuing pricing](https://stripe.com/us/issuing)). Standard programs have built-in limits; contact Stripe to raise them. — [nevermined.ai Stripe Issuing review](https://nevermined.ai/blog/stripe-issuing-review); [Stripe docs: Issuing for your business](https://docs.stripe.com/issuing/for-your-business?locale=en-GB)
- Lithic offers virtual cards with "Auth Rules" covering merchant category, amount, velocity and time of day, and has an agentic-commerce page. No public 2026 per-card price was found. A buyer's guide says Lithic leaves approvals, identity and audit to the developer. — [Lithic agentic commerce](https://www.lithic.com/solutions/agentic-commerce); [Lithic card issuing](https://www.lithic.com/card-issuing); [agentspay.ai](https://agentspay.ai/blog/best-agent-payment-platforms)

**Google Agent Payments Protocol (AP2)**
- v0.2.0 was released in April 2026, and Google gave AP2 to the FIDO Alliance in April 2026. It has a "Human Not Present" flow for autonomous purchases under pre-authorized mandates, and reportedly more than 100 supporting organizations (Mastercard, PayPal, Coinbase, Lightspark). Sources disagree on the mandate model: Intent/Cart/Payment in older versions, Checkout/Payment with open and closed stages in v0.2. — [eco.com AP2 2026](https://eco.com/support/en/articles/15192002-ap2-protocol-explained-google-s-agentic-commerce-standard-2026); [mintmcp.com](https://www.mintmcp.com/blog/ap2-agent-payments-protocol)

### Inferences
- **Apple Pay (inferred; Apple Pay's per-transaction Face ID/Touch ID/passcode requirement is background knowledge, not re-checked this session):** Macoma cannot "use Apple Pay" for an owner on its own. Apple Pay can appear in two places only: (1) on the selling side, when the owner's customer pays a Macoma/Stripe invoice or Payment Link on their own iPhone; and (2) at a gate where the owner approves a purchase on a page that offers Apple Pay. For agent buying, the equivalent is enrolling once (with biometrics) in Link or a network agentic token, then approving each purchase in the Link app.
- SPT, ACP and AP2 only work if the merchant supports them. Most supply vendors that one-person service businesses use (local supply houses, Home Depot, Amazon) will not accept an SPT directly. Universal acceptance today comes from a card number: a Link one-time card or an Issuing virtual card.
- For Macoma's first two weeks, the lowest-liability path is Link's agent wallet: the card never touches Macoma, and the approval happens in Stripe's app. Issuing for agents is the next step once Macoma wants owner-funded cards with merchant locks and budgets. Becoming an Issuing program brings KYB, compliance and funding duties.
- x402 suits Macoma paying for APIs or data per call. It does not fit buying supplies.

### Gaps
- [corrected in verification] Link's agent wallet does have published limits and eligibility: $500 per request, $500 per day, US individuals only. No fees were found. Issuing for agents requires private-preview access requested through Stripe sales.
- Neither product publishes fees. No source says whether a business, as opposed to an individual Link account, can use the agent wallet.
- No official Visa or Mastercard developer pages were reachable, so their fees and startup eligibility are unconfirmed.
- No Lithic price card was found.
- No primary Apple statement on agents and Apple Pay was found. The conclusion above is inference.

## 3. Browser-acting agents an app can drive through an API: pricing, reliability, CAPTCHAs, logins, legal and terms-of-service risk

### Takeaway
To get the job done, pair a model that can act on screens with a hosted browser. Claude's `computer_toolset_20260801` on Sonnet 5.5, Opus 5.5 or Haiku 5.5 is generally available. Gemini's computer-use tool or OpenAI's computer use are alternatives. Run it on Browserbase, Steel, Hyperbrowser or Browser Use Cloud, each about $0.02–0.12 per browser-hour. Claude in Chrome is a consumer extension, not a server API. The largest risks are bot blocking and retailer terms, not legality under the anti-hacking law (CFAA): Amazon blocked Meta Muse in September 2026, and the Ninth Circuit's ruling for Perplexity is narrow.

### Cited Findings
**Anthropic computer use (Claude API)**
- `computer_toolset_20260801` is generally available on the Claude API and Google Cloud with no beta header. It is one `tools` entry, `{"type":"computer_toolset_20260801"}`, with 17 member tools (screenshot, left_click, type, zoom…) and optional `configs` to switch members off. Claude Opus 5.5 and Sonnet 5.5 accept only this toolset on the Claude API and Google Cloud; the older `computer_20251124` returns a 400 there but still works on Bedrock. Haiku 5.5 also uses the toolset. — [Anthropic docs: computer use tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool.md) (via the claude-api skill reference)
- Computer use runs on the client side. The app provides and runs the environment (a VM or container with minimal privileges), and Anthropic "does not host the environment." — [Anthropic docs: computer use tool, security considerations](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool#security-considerations)
- Token prices per million (input/output), cached 2026-10-06: Opus 5.5 $4/$20; Sonnet 5.5 $2/$10 (cache reads $0.20); Haiku 5.5 $0.10/$0.50 for prompts up to 100K tokens. Fast mode on Opus 5.5 costs $8/$40. — [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing.md)
- **Claude in Chrome** became generally available on 26 Aug 2026 for paid plans (Pro, Max, Team, Enterprise). It is desktop Chrome only. It can now approve actions it judges safe automatically (a setting the user can turn off). A January 2026 prompt-injection exploit ("ShadowPrompt") was patched in v1.0.41. — [GIGAZINE](https://gigazine.net/gsc_news/en/20260827-claude-chrome-available/); [ai-toolbox.co](https://www.ai-toolbox.co/claude-management-and-productivity/claude-for-chrome-setup-limits-2026); [explainx.ai](https://explainx.ai/blog/claude-in-chrome-browser-extension-guide-safety-2026)

## 5. LangChain/LangGraph or Claude's own tools for "Claude plans, a browser agent acts": is a framework needed?

### Takeaway
No framework is needed. Claude's tool use already covers "Claude plans, a browser agent acts, a person approves." The options are the SDK Tool Runner with per-turn hooks for approval gates, the Claude Agent SDK, and Managed Agents with `always_ask` permission policies, vaulted credentials and MCP. In this design, Macoma's order flow is a state machine in its own Node code, and the browser is one tool. LangGraph helps mainly when you need provider-agnostic, durable graph state.

### Cited Findings
- Anthropic's API offers four ways to build an agent:
  - a manual loop;
  - the SDK Tool Runner (`client.beta.messages.toolRunner`, harness only), whose per-turn hooks give "approval gates, logging, error interception";
  - Managed Agents (Anthropic hosts the loop and a per-session container);
  - the Claude Agent SDK (the Claude Code harness as a library).
  — [Anthropic docs: Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview.md); [Claude Agent SDK docs](https://code.claude.com/docs/en/agent-sdk) (via the claude-api skill reference)
- Managed Agents permission policies:
  - `always_ask` pauses the session until a `user.tool_confirmation` event arrives; it is the default for MCP toolsets.
  - `auto` lets the server run, deny or pause each call.
  - Vault credentials are "substituted at egress, never visible in the sandbox."
  - Scheduled deployments run sessions on a cron schedule.
  — [Anthropic docs: permission policies](https://platform.claude.com/docs/en/managed-agents/permission-policies.md); [vaults](https://platform.claude.com/docs/en/managed-agents/vaults.md); [MCP connector](https://platform.claude.com/docs/en/managed-agents/mcp-connector.md)
- Blog comparisons:
  - LangGraph is "a low-level orchestration runtime where you own the loop, the state schema, and every edge," and is strongest on durable state, interrupts and approvals, and model choice.
  - The Claude Agent SDK is tied to Claude and gives "direct… integration with browser vision and desktop control."
  - Several suggest a hybrid: LangGraph on top, Claude Agent SDK subagents in its nodes.
  - These are blogs; none benchmarks browser agents.
  — [developersdigest.tech](https://www.developersdigest.tech/blog/claude-agent-sdk-vs-langgraph); [nerova.ai](https://nerova.ai/comparisons/claude-agent-sdk-vs-langgraph-2026); [mager.co](https://www.mager.co/blog/2026-03-07-langgraph-claude-agent-sdk-ultimate-guide/); [turion.ai](https://turion.ai/blog/langgraph-vs-openai-claude-agent-sdk-2026/)
- Off-the-shelf browser agents can also be called as tools: Stagehand/Browserbase, Browser Use Cloud hosted agents (model cost + 20%), and Browserless's Link checkout MCP tools. — [skyvern.com](https://www.skyvern.com/blog/browserbase-vs-stagehand-which-is-better/); [browser-use.com](https://browser-use.com/cloud-browsers); [Browserless](https://www.browserless.io/blog/agentic-checkout-stripe-link)

### Inferences
- The recommended Macoma pattern, in its existing Node/TypeScript code:
  1. Claude (Sonnet 5.5 for chat, Opus 5.5 for hard planning) turns "reorder my usual supplies" into a structured order draft using a strict tool schema.
  2. Macoma stores the draft as an order record with states: draft → quoted → awaiting YES → paying → placed / failed.
  3. Only after the owner's YES and a confirmed cart total does Macoma call the "act" tool. That tool is a supplier API, a cart link, or a browser sub-agent (Claude computer use on Browserbase or Steel, or Stagehand).
  4. The browser sub-agent never sees a real card. It receives a Link one-time card or an Issuing virtual card at the payment step.
- This matches Macoma's existing "texts customers after the owner replies YES" pattern. A framework adds dependencies without adding a capability Macoma lacks.

## 6. Recommended ordering architecture for Macoma, with liability and fraud controls

### Takeaway
Use four tiers, cheapest and safest first:
1. Direct supplier or partner APIs (Shopify agent checkout, Instacart links, Amazon Business where the owner has it).
2. Pre-filled cart links the owner taps and pays for themselves.
3. A browser agent behind a text confirmation ("Reply YES to buy 3 items, $142.18 from X").
4. A Stripe Link one-time card (and later Issuing virtual cards with merchant and amount locks), so Macoma never holds a real card number.

Make the owner the buyer, as Instinct's terms do. Keep audit logs.

### Cited Findings
- **Tier 1 / Tier 2 building blocks:**
  - The Instacart Developer Platform API generates shoppable recipe or list links. Developers get a link to an Instacart-hosted page where the user checks out, with no Instacart data access. Its docs mention connecting an AI agent or LLM. — [Instacart docs](https://docs.instacart.com/developer_platform_api); [Instacart announcement](https://company.instacart.com/updates/the-instacart-developer-platform-a-new-way-to-turn-inspiration-into-action)
  - Amazon Business supports punchout from e-procurement systems (Coupa, Ariba, Jaggaer), with the cart returned for policy checks, plus APIs and an App Center. — [Amazon Business blog](https://business.amazon.com/en/blog/cio-procurement-integrations); [Procurify guide](https://success.procurify.com/en/articles/14479451-amazon-punchout-integration-overview-and-setup-guide)
  - Shopify's agent checkout lets a partner agent build an order and pay with Shop Pay. Partners named in coverage are Instinct and Muse. — [TechCrunch](https://techcrunch.com/2026/09/28/shopify-opens-checkout-to-browser-based-ai-agents/)
- **Tier 3:** Every leading consumer agent gates purchases on approval: Instinct (amount approval), Muse ("approve sensitive actions like… making purchases," with an audit trail), Claude Duet ("waits for approval before… making a payment"), and Stripe Link (approval in the Link app). — [eesel.ai](https://www.eesel.ai/blog/instinct-ai-review); [layer3labs Muse](https://www.layer3labs.io/guides/meta-muse-review); [PYMNTS Claude Duet](https://www.pymnts.com/news/artificial-intelligence/2026/anthropics-new-ai-agent-purchases-business-supplies/); [TechCrunch Link](https://techcrunch.com/2026/04/30/stripe-link-digital-wallet-ai-agents-shopping/)
- **Tier 4 controls:** Stripe Issuing for agents supports per-agent limits, merchant-category locks, per-transaction and per-period limits, and single-use cards. Lithic Auth Rules add velocity and time-of-day limits. Browserless's Link checkout reportedly caps purchases at $50 (unverified). [corrected in verification] Link itself caps each spend request at $500 and each account at $500 per day. — [Stripe docs](https://docs.stripe.com/issuing/agents); [Lithic](https://www.lithic.com/card-issuing); [Browserless](https://www.browserless.io/blog/agentic-checkout-stripe-link)
- **Liability model:** Instinct's terms say the user is the buyer and Instinct is not processing the payment, appoint Instinct as the user's agent, and cap liability at the greater of $100 or six months of fees. — [instinct.co/terms](https://instinct.co/terms); [layer3labs](https://www.layer3labs.io/comparisons/instinct-ai-vs-poke)
- **Dispute evidence:** Mastercard Verifiable Intent creates a tamper-resistant record of identity, instructions and outcome. AP2 mandates play a similar role. — [eco.com](https://eco.com/support/en/articles/15192003-mastercard-agent-pay-vs-visa-trusted-agent-2026-compared); [mintmcp.com](https://www.mintmcp.com/blog/ap2-agent-payments-protocol)
- **Fraud and prompt-injection risk is documented:** an email reached an Instinct user's contact without approval; Instinct's Privacy Notice warns of unintended payments through hidden instructions; a Claude in Chrome injection exploit was patched in 2026. — [eesel.ai](https://www.eesel.ai/blog/instinct-ai-review); [explainx.ai](https://explainx.ai/blog/claude-in-chrome-browser-extension-guide-safety-2026)
- **Competitive context:** Anthropic's Claude Duet (21 Oct 2026, waitlist) targets small-business owners and buys supplies through Link. — [PYMNTS](https://www.pymnts.com/news/artificial-intelligence/2026/anthropics-new-ai-agent-purchases-business-supplies/)

### Inferences
- **Suggested Macoma flow (design inference):**
  1. The owner texts "reorder gloves and filters."
  2. Claude matches the request to the owner's saved supplier list and last order.
  3. Tier 1 if a supplier API or partner exists. Otherwise Tier 2: text a cart link ("Tap to review and pay: …"). This is zero liability and needs no card.
  4. If the owner turns on "buy for me," Tier 3 and 4: the browser agent builds the cart in a Browserbase or Steel session. Macoma texts back the exact merchant, items and total. Only after YES (matched to that order ID and total, and expiring after about 15 minutes) does Macoma request a Link one-time card for exactly that amount, which the owner approves in Link. The agent then checks out, and Macoma texts back the receipt or confirmation number.
- **Controls to build:**
  - a per-owner monthly agent-spend cap and per-order cap (for example, start at $250); [corrected in verification] Link's hard limits are $500 per request and $500 per day per Link account, shared across every agent the owner has connected, and the wallet is for US individual accounts only. A supply run over $500 a day therefore cannot go through Link and needs Issuing or a cart link;
  - a list of allowed merchants;
  - a block on new merchants without a second confirmation;
  - the total must match the approved amount exactly (re-confirm on any change);
  - no stored retailer passwords in v1 (owner taps the link, or uses guest checkout with Link);
  - the browser agent treats page text as untrusted (prompt-injection defence) and cannot send messages or reach other tools;
  - a full audit log with screenshots of the order state;
  - a kill switch, "STOP" by text.
- **Liability posture (needs counsel review):** the terms should make the owner the buyer and Macoma the owner's limited agent acting only on explicit per-order YES, not a merchant of record. Disputes go to the merchant or card issuer. Liability is capped. Macoma should not hold card numbers (Link or Issuing tokens only), which keeps PCI scope minimal.
- **Two-week MVP:** build Tier 2 (cart links) plus the YES gate and order log first. Run Tier 3 and 4 as a pilot on Shopify stores, and apply for Link wallet and Issuing for agents access in parallel.

### Gaps
- No public "supplier API" catalogue was found for typical trades suppliers (Home Depot Pro, Ferguson, Grainger, Sherwin-Williams). Availability needs a per-supplier check.
- Whether Stripe would approve a one-person startup for Link's agent wallet or Issuing for agents is unknown. Neither has public eligibility criteria.
- No US regulatory guidance specific to agent-initiated business purchases (for example, Reg E/Z treatment of agent-initiated card payments) was found in this session.
